# خُلد — Khold

لعبة حفر بكسل ثنائية الأبعاد للجوال، مفتوحة المصدر، مبنية بـ **Godot 4.7**.
احفر التراب، اجمع كل الثمار، افتح المخرج، واحذر الصخور المتساقطة.

اللعبة أصلية بالكامل: كل الرسومات تُرسم بالكود، وكل المؤثرات الصوتية تُولّد داخل
المشروع. لا توجد أصول فنية أو صوتية منسوخة من أي لعبة أخرى.

---

## المزايا

- **لعبة كاملة**: حفر، دفع صخور، جاذبية، ثمار، مخرج مقفل، تراجع، إعادة، موت ونجاح.
- **10 مراحل حملة** بتصميم تدريجي، مع «هدف الحركات» وتقييم بالنجوم.
- **تحكم لمس أولًا**: اسحب على اللوحة أو استخدم لوحة الأسهم الكبيرة، مع دعم لوحة
  المفاتيح (الأسهم أو WASD) على الكمبيوتر.
- **محرر مراحل داخل اللعبة**: سبع أدوات رسم، اختبار فوري، حفظ محلي.
- **قسم مراحل الإنترنت**: نشر، تصفح، تنزيل، لعب، تقييم، وإبلاغ.
- **يعمل دون اتصال**: المراحل المنزّلة والمحلية تُحفظ على الجهاز.
- **واجهة عربية RTL** بخط Almarai المضمّن (رخصة SIL OFL).
- **خادم مراحل صغير** بلا اعتماديات خارجية: Python + SQLite، أو نسخة سحابية
  جاهزة على **Cloudflare Workers + D1**.

## التشغيل السريع

### المتطلبات

- **Godot 4.7.2** (نسخة قياسية أو .NET غير مطلوبة).
- **Python 3.10+** اختياري، فقط لتشغيل خادم المراحل.

### من محرر Godot

1. افتح Godot ثم `Import` واختر ملف `project.godot` في هذا المجلد.
2. اضغط **F5** أو زر التشغيل.

### من سطر الأوامر

```powershell
# استيراد المشروع أول مرة
godot --headless --path . --editor --quit

# تشغيل اللعبة
godot --path .
```

> إعدادات المشروع مضبوطة على شاشة عمودية 720×1280 مع وضع تمدد
> `canvas_items` / `expand`، لذا تعمل على شاشات الجوال المختلفة.

## طريقة اللعب

| العنصر | المعنى |
| --- | --- |
| الخلد | اللاعب |
| التراب البني | قابل للحفر |
| الصخر | يُدفع أفقيًا فقط، ويسقط عند وجود فراغ تحته |
| الفولاذ | جدار لا يُكسر |
| الثمرة | اجمعها كلها |
| المخرج | يُفتح بعد جمع آخر ثمرة |

- **الهدف**: جمع كل الثمار ثم الوصول إلى المخرج بأقل عدد حركات.
- **الموت**: إذا سقط صخر على الخلد. استخدم «تراجع» أو «إعادة».
- **النجوم**: 3 نجوم عند الوصول ضمن 115% من الهدف، ونجمتان ضمن 155%، وإلا نجمة.
- **التحكم**:
  - اسحب فوق لوحة اللعب في اتجاه الحركة.
  - أو استخدم لوحة الأسهم.
  - على الكمبيوتر: الأسهم أو WASD، و`Esc` للإيقاف المؤقت.
- **أزرار اللعب**: «تراجع» للخطوة السابقة، «إعادة» لإعادة المرحلة من البداية.

## صيغة المراحل

كل مرحلة عبارة عن مصفوفة صفوف متساوية الطول. الرموز:

| الرمز | المعنى |
| --- | --- |
| `.` | تراب |
| ` ` (مسافة) | فراغ |
| `R` | صخر |
| `S` أو `#` | فولاذ |
| `F` أو `*` | ثمرة |
| `E` | مخرج |
| `P` | نقطة بداية اللاعب |

مثال (12×16):

```text
SSSSSSSSSSSS
SP.........S
S..F.......S
S..........S
S.........ES
SSSSSSSSSSSS
```

الحد الأدنى 7×7 والأقصى 24×32، مع لاعب واحد ومخرج واحد وثمرة واحدة على الأقل.

## محرر المراحل

1. من القائمة: **محرر المراحل**، أو من قائمة المراحل: **مرحلة جديدة**.
2. اكتب اسم المرحلة، وارسم بإصبعك على اللوحة.
3. الأدوات: تراب، فراغ، صخر، فولاذ، فاكهة، مخرج، لاعب.
4. **اختبار المرحلة** يشغّل نسخة تجريبية كاملة قبل الحفظ.
5. **حفظ** يخزّن المرحلة في `user://levels` لتظهر في «مراحلي».
6. يمكن لعب المرحلة أو تعديلها أو حذفها من قائمة المراحل.
7. لنشرها للآخرين: افتح **مراحل الإنترنت** ثم اضغط **نشر**.

> يتحقق المحرر من وجود لاعب ومخرج وثمرة واحدة على الأقل، ومن قابلية الوصول
> المبدئية. المراحل المحفوظة تبقى على الجهاز حتى لو لم يوجد اتصال.

## خادم المراحل (اختياري)

الخادم مكتوب بـ Python القياسي فقط، ويستخدم SQLite. لا يحتاج `pip` ولا أي حزمة
خارجية.

```powershell
python server/server.py --host 0.0.0.0 --port 8787
```

سيطبع عنوان الشبكة المحلية، مثل:

```text
Khold level server listening on http://0.0.0.0:8787
LAN URL for phones: http://192.168.1.10:8787
Database: ...\server\khold.db
```

- على الكمبيوتر: عنوان الخادم `http://127.0.0.1:8787`.
- على جوال حقيقي: استخدم عنوان IP للكمبيوتر على نفس شبكة Wi-Fi، مثل
  `http://192.168.1.10:8787`، ثم اضغط «اتصال» في شاشة الإنترنت.
- يمكن تغيير العنوان من **الإعدادات ← خادم المراحل** أو من شاشة الإنترنت مباشرة.

### واجهة الخادم

| الطريقة | المسار | الوظيفة |
| --- | --- | --- |
| `GET` | `/health` | فحص سريع وعدد المراحل الظاهرة |
| `GET` | `/levels?limit=60&offset=0` | قائمة المراحل المنشورة |
| `GET` | `/levels/{id}` | تفاصيل مرحلة مع بياناتها |
| `POST` | `/levels` | نشر مرحلة |
| `POST` | `/levels/{id}/play` | زيادة عدّاد اللعب |
| `POST` | `/levels/{id}/rate` | تقييم 1–5 (صوت واحد لكل `client`) |
| `POST` | `/levels/{id}/report` | إبلاغ؛ 3 بلاغات مختلفة تخفي المرحلة |

مثال نشر:

```json
{
  "name": "مرحلة الاختبار",
  "author": "لاعب",
  "data": {
    "w": 12,
    "h": 16,
    "rows": ["SSSSSSSSSSSS", "SP.........S", "S..F.......S", "S.........ES", "SSSSSSSSSSSS"],
    "par": 12
  }
}
```

### ملاحظات الإنتاج

- الخادم لا يوفر حسابات أو مصادقة؛ هو نموذج أولي مناسب للتجربة على الشبكة
  المحلية. للإنتاج أضف HTTPS، وحدًا لمعدل الطلبات، ومراجعة بشرية للبلاغات.
- خذ نسخة احتياطية من `server/khold.db` بانتظام.
- غيّر `REPORT_HIDE_THRESHOLD` أو منطق الإخفاء إذا أردت مراجعة يدوية.
- لا تشغّل `--host 0.0.0.0` على شبكة عامة دون جدار حماية مناسب.

## الاستضافة على Cloudflare (موصى به للجوال)

نسخة جاهزة من الخادم موجودة في `server/cloudflare/` وتعمل على
**Cloudflare Workers + D1**، دون تشغيل جهازك. اللعبة لا تحتاج أي تعديل: ضع رابط
Worker في حقل «عنوان الخادم» داخل شاشة الإنترنت.

```powershell
cd server/cloudflare
npx wrangler login
npx wrangler d1 create khold-levels
# ضع database_id الناتج في wrangler.toml
npx wrangler d1 migrations apply khold-levels --remote
npx wrangler deploy
```

سيطبع رابطًا مثل `https://khold-levels.<account>.workers.dev`، وهو صالح
لجميع اللاعبين. التفاصيل الكاملة وخطوات النشر التلقائي من GitHub في
[`server/cloudflare/README.md`](server/cloudflare/README.md).

### الربط بـ GitHub

المشروع مهيأ للعمل كمستودع Git عادي. سير العمل المضمّن:

- `.github/workflows/ci.yml`: يختبر خادم Python، ويبني Worker تجريبيًا، ويشغّل
  اختبارات Godot كاملة على كل دفعة أو طلب سحب.
- `.github/workflows/deploy-worker.yml`: ينشر Worker ويطبّق ترحيلات D1 عند
  الدفع إلى `main`، بعد إضافة السرّين `CLOUDFLARE_API_TOKEN` و
  `CLOUDFLARE_ACCOUNT_ID` والمتغير `CLOUDFLARE_DEPLOY=true` في إعدادات
  المستودع.

> الخادم السحابي المنشور لهذا المشروع:
> `https://khold-levels.mayam33.workers.dev` — وهو العنوان الافتراضي في اللعبة.

## الاختبارات

```powershell
# التحقق من قابلية حل كل مراحل الحملة وطباعة أهداف الحركات
godot --headless --path . --script res://tools/solve.gd

# اختبار المنطق: الحفر، الدفع، الجاذبية، الموت، النجوم، المحلل
godot --headless --path . res://tools/test_mechanics.tscn

# اختبار الواجهات: القائمة، اللعب، التراجع، المحرر، الإنترنت
godot --headless --path . res://tools/test_ui.tscn

# اختبار واجهة الخادم (يشغّل خادم Python مؤقتًا تلقائيًا)
python tools/test_server.py

# اختبار نسخة Cloudflare أثناء تشغيل wrangler dev
python tools/test_server.py --base http://127.0.0.1:8788

# فحص اتصال عميل Godot بالخادم السحابي المنشور
godot --headless --path . res://tools/test_cloud.tscn
```

> يحتاج اختبار الواجهة إلى تشغيل خادم المراحل على `127.0.0.1:8787`.
> النتيجة الحالية: **35 فحصًا ناجحًا** في كل من اختباري المنطق والواجهة،
> **25 فحصًا** لواجهة الخادم، و**10 مراحل قابلة للحل**.

## التصدير إلى الجوال

### بناء APK جاهز من GitHub

أضفنا سير عمل `.github/workflows/build-android.yml` الذي ثبّت قوالب Godot و
Android SDK ويصدّر APK موقّعًا بتصحيح الأخطاء (debug):

1. افتح تبويب **Actions** في المستودع، ثم اختر **Build Android APK**.
2. اضغط **Run workflow**، وانتظر اكتماله.
3. نزّل الملف `khold-apk` من تبويب **Artifacts**، وافكّ ضغطه لتحصل على `khold.apk`.

يمكن أيضًا تشغيله تلقائيًا بدفع وسم يبدأ بـ `v` مثل `v1.0.0`.
اسم الحزمة: `com.mayam33.khold`، والاتجاه عمودي.

### أندرويد (محليًا)

1. نزّل **Export Templates** لنسخة Godot 4.7.2 من
   `Editor → Manage Export Templates`.
2. ثبّت Android SDK وحدد مساره في `Editor Settings → Export → Android`.
3. أنشئ مفتاح توقيع:

   ```powershell
   keytool -genkey -v -keystore khold.keystore -alias khold `
     -keyalg RSA -keysize 2048 -validity 10000
   ```

4. من `Project → Export` أضف إعداد **Android**، اختر الحزمة `com.example.khold`،
   وحدد الـ keystore.
5. صدّر APK أو AAB. الاتجاه مضبوط مسبقًا على الوضع العمودي.

### iOS

1. يلزم جهاز macOS مع Xcode.
2. نزّل Export Templates، ثم أضف إعداد **iOS** من `Project → Export`.
3. صدّر مشروع Xcode، وافتحه لتوقيع التطبيق وتشغيله على الجهاز.

### ملاحظات الجوال

- التحكم باللمس مفعّل، ووضع `emulate_touch_from_mouse` مناسب للتجربة على الكمبيوتر.
- الاهتزاز يعمل فقط على الأجهزة المحمولة المدعومة.
- الصوت مُولّد في الذاكرة، لذا حجم التطبيق صغير ولا يحتاج ملفات صوتية.
